# Textures

Everything in `assets/textures/` is generated by one script:

```
python3 tools/make_textures.py               # all textures, manifest, _preview.jpg
python3 tools/make_textures.py --only quartz # just one (repeatable); merges into manifest.json
python3 tools/make_textures.py --no-preview  # skip the contact sheet
```

It needs only Python 3, Pillow and numpy, runs in about 50 s, and gives the
same files every time (fixed seeds, no randomness from the clock).

## Manifest

`assets/textures/manifest.json` is a JSON **array**. Each entry looks like this:

```json
{"name": "wainscot", "map": "wainscot_albedo.jpg", "normalMap": "wainscot_normal.png",
 "roughnessMap": "wainscot_rough.png", "physicalSizeM": [1.2192, 0.6096],
 "repeat": [0.8202, 1.6404]}
```

- `physicalSizeM` is the real-world `[width, height]` that one copy of the
  image covers. `repeat` is just `1 / physicalSizeM` (repeats per metre).
- Some entries have extra fields: `color` (the mean sRGB hex of the albedo,
  for `wall_paint` and `door_slab`), `alphaMap` (only `rattan`), and
  informational keys such as `tileSizeIn`, `plankAxis` and `grain`.
- Albedo maps are sRGB JPEGs (q90). Normal and roughness maps are PNGs in
  linear space.
- **Normal maps use the OpenGL convention (+X right, +Y up = green)**, which
  is what Three.js expects. Do not flip green, and leave `normalScale` at (1, 1).
  The bevel and grout depths are in true millimetres for the stated physical size.
- Roughness and alpha maps are greyscale. Three.js reads the G channel, and
  all three channels are equal.
- The albedo already carries the surface colour, so set the material `color`
  to white (0xffffff). A tinted colour multiplies the colour in a second time.

## Sources

textures come instead from the makers' images in `assets/source/wallpapers/`,
whose URLs, specs and identification are in `SOURCES.md` there. They are
cropped to whole pattern repeats, with no cross-fade and no colour change.
See `docs/ADDING_OPTIONS.md`, recipe 3.

### Colour balance

The photos were taken under mixed light: warm vanity bulbs, blue daylight,
and store lighting for 00 and 01. Each photo patch is first flattened: every
channel is divided by a wide Gaussian blur of itself, which removes light
falloff and shading. Then each channel is scaled, in linear light, so the
mean matches a neutral target colour. The targets come from white-reference
patches in the same photos (toilet, tub, white display tile, drywall), with
the result checked against the photos by eye:

`floor_plank` #4A433F · `wainscot` #8A8581 · `accent_band` #383637 ·
`vanity_wood` #5A5550 · `quartz` #DAD7D2 · `wall_paint` #B8BFBB ·
`rattan` #8D7865 · `wood_frame` #7A4238 · `curtain` #6B6C74 ·
`door_slab` #6B6C6B · sage glaze #7E8676

The targets are constants in the builder functions. Change one there and re-run.

## Adding a texture for a new tile option

1. Add a `tex_<name>()` function to `tools/make_textures.py` and register it
   in `BUILDERS` and `ORDER`.
   - For a **grouted tile**, call `compose_tiles(W, H, tile_w_px, tile_h_px,
     offset_frac, tile_fn, grout_hw, grout_lin, bevel_px, bevel_mm,
     grout_depth_mm, grout_rough, seed)`. `tile_fn(row, col, TW, TH)` returns
     `(albedo_linear, height_mm, roughness)` for one tile face. See
     `tex_tile_white_subway_stacked` (procedural faces) or `tex_wainscot`
     (photo faces).
   - Make the repeat a whole number of tiles in both directions, including
     the row offset. For example, a 1/3 offset needs 3 rows.
   - For a **photo** surface, rectify it with
     `warp(photo(i), [TL, TR, BR, BL], w, h)`, then use
     `prep_photo_patch(..., flat_sigma, target="#hex")`, then
     `make_tileable(...)`.
   - Pick the pixels-per-inch from the physical size of the repeat:
     2048 px for large surfaces, 1024 px otherwise.
2. Return `entry(name, albedo_lin, (w_m, h_m), normal_map(height_mm, px_mm), rough)`.
3. Run `python3 tools/make_textures.py --only <name>`, then open
   `assets/textures/_preview.jpg`. The preview tiles every albedo 2x2, so
   seams show up there.
4. On the app side, add an option file under `src/options/tiles/` whose
   `makeMaterial(ctx)` uses `ctx.textures` by the same name (see
   `docs/ADDING_OPTIONS.md`).
